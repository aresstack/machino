# Machino HTTP API v1

Stable, platform-neutral control and telemetry interface for a WebUI.
Everything a UI needs — which controls exist, whether they are supported,
how a change takes effect, what the effective state is — comes from this
API. A UI never needs to know a SoC or sensor name.

```
WebUI -> HTTP /api/v1 -> ApiService -> PerformanceService / PipelineManager / ConfigStore / EventBus
```

* Base path `/api/v1`, JSON bodies, `Content-Type: application/json`.
* Default bind `0.0.0.0:8080` (`api.bind`, `api.port`, `api.enabled` in `machino.conf`).
* **API access is never media demand**: reading state/telemetry/capabilities
  or holding an `/events` connection does not start the camera pipeline.
* Limits: request head ≤ 8 KB, body ≤ 8 KB, JSON depth ≤ 16, strings ≤ 4096,
  16 concurrent clients, 64 KB output buffer per client (slow clients are
  disconnected), 30 s keep-alive idle timeout. No shell, no file paths.

## Endpoints

| method | path | purpose |
|---|---|---|
| GET | `/api/v1` | discovery |
| GET | `/api/v1/capabilities` | what the platform/board/sensor offers; control status + apply mode |
| GET | `/api/v1/state` | effective runtime state |
| GET | `/api/v1/config` | persistent configuration (WebUI shape) + revision |
| PATCH | `/api/v1/config` | partial change; applied via services, persisted atomically |
| GET | `/api/v1/telemetry` | snapshot; unavailable values are `null` |
| GET | `/api/v1/events` | Server-Sent Events: `lifecycle`, `config_changed`, `telemetry`, `error`, `state` |

`OPTIONS` answers CORS preflight (`Access-Control-Allow-Origin: *`).

## Status codes

| code | meaning |
|---|---|
| 200 | success |
| 204 | preflight |
| 400 | malformed request: `invalid_json`, `unknown_field` |
| 404 | unknown endpoint |
| 405 | method not allowed |
| 409 | `conflict` — stale revision |
| 413 | request too large |
| 422 | semantically invalid: `invalid_value`, `unsupported_control` |
| 500 | `internal_error`, `apply_failed`, `pipeline_restart_failed` |
| 503 | `unavailable` (too many clients) |

## Error format

```json
{ "ok": false, "error": { "code": "invalid_value", "path": "sensor.fps", "message": "fps must be an integer in 1..240" } }
```

Codes: `invalid_json`, `invalid_value`, `unknown_field`, `unsupported_control`,
`unavailable`, `conflict`, `apply_failed`, `pipeline_restart_failed`,
`internal_error`. Never a bare 500 without a machine-readable cause.

## GET /api/v1

```json
{ "name": "Machino", "version": "…", "api": 1,
  "endpoints": { "capabilities": "/api/v1/capabilities", "state": "/api/v1/state",
                 "config": "/api/v1/config", "telemetry": "/api/v1/telemetry", "events": "/api/v1/events" } }
```

## GET /api/v1/capabilities

```json
{
  "api": 1,
  "platform": { "vendor": "ingenic", "family": "t40", "model": "t40nn" },
  "board":    { "id": "t40nn-imx307-board-a", "hardware_verified": true },
  "sensor":   { "model": "imx307", "interface": "mipi-csi", "native": { "width": 1920, "height": 1080 },
                "modes": [ { "width": 1920, "height": 1080, "fps": [20, 15, 10] } ] },
  "video":    { "h264": "supported", "h265": "unknown", "max_streams": null },
  "controls": {
    "sensor_fps":    { "status": "supported", "apply": "live", "min": 10, "max": 20 },
    "stream_fps":    { "status": "supported", "apply": "pipeline_restart", "min": 10, "max": 20 },
    "bitrate":       { "status": "supported", "apply": "live" },
    "isp_clock":     { "status": "unsupported", "apply": "unsupported", "readable": true },
    "encoder_clock": { "status": "unsupported", "apply": "unsupported", "readable": true },
    "cpu_frequency": { "status": "unsupported", "apply": "unsupported", "readable": true },
    "idle_grace_ms": { "status": "supported", "apply": "daemon_restart" }
  },
  "profiles": ["performance", "balanced", "battery", "custom"],
  "verified_fps": [10, 15, 20]
}
```

Semantics:

* `status`: `supported | unsupported | unknown`. **`unknown` is not `unsupported`**
  — the adapter has not established it. A UI hides `unsupported`, may show
  `unknown` as disabled.
* `apply`: `live | pipeline_restart | daemon_restart | boot_only | unsupported`
  (from the M5 apply model).
* `readable`: the current value can be read (it then appears in telemetry)
  even when `status` is `unsupported` — e.g. the T40 CPU/ISP/encoder clocks
  are readable from the kernel but not controllable.
* `min`/`max` are present **only when known**; absent means unknown — the
  server never invents bounds. Values outside a known range are rejected.
* `sensor.modes[].fps` lists **verified** operating points only. Values not
  listed are rejected unless the daemon runs with
  `sensor.allow_unverified_mode = 1` (qualification runs).

## GET /api/v1/state

Effective runtime state (what is, not what was asked):

```json
{
  "lifecycle": "active",              // cold_idle | starting | active | grace_idle | stopping | failed
  "profile": "custom",
  "pipeline_generation": 3, "restarts": 1, "last_error": null,
  "consumers": { "total": 1, "rtsp": 1 },
  "media": { "sensor_fps_requested": 15, "sensor_fps": 15, "stream_fps": 15, "bitrate_kbps": 1500,
             "width": 1920, "height": 1080, "encoder_active": true },
  "revision": 4
}
```

`media.sensor_fps` is the value read back from the ISP; it is `null` while the
pipeline is cold or the platform cannot read it. `sensor_fps_requested` is the
configured value. `bitrate_kbps` / `stream_fps` are the values the running (or
next) pipeline uses.

```json
  "power": { "isp_performance": "auto", "encoder_performance": "auto", "cpu_performance": "auto" }

```

## PATCH /api/v1/config

Partial update. Only the given fields change; nothing else is reset.

Writable paths: `performance.profile`, `sensor.fps`, `video.0.fps`,
`video.0.bitrate_kbps`, `video.0.gop`, `latency.profile`,
`latency.gop`, `latency.framesource_buffers`, `latency.encoder_buffers`,
`latency.consumer_queue_depth`, `latency.socket_send_buffer_bytes`,
`latency.send_stall_ms`, the supported `image.*` controls,
`lifecycle.idle_grace_ms`, `power.isp_performance`,
`power.encoder_performance`, `power.cpu_performance`. Optional optimistic
concurrency: header `If-Match: <revision>` or body field `"revision"`; a stale
revision yields `409 conflict`.

Processing order: (1) structural validation of the whole document — unknown
field, wrong type, out-of-range or unverified value → nothing is applied
(400/422); (2) apply in order (profile first, then explicit values — explicit
values win); (3) persist the applied/stored values atomically (temp file →
fsync → rename), `revision++`, emit `config_changed`.

Request:
```json
{ "video": { "0": { "bitrate_kbps": 1500 } } }
```
Response (pipeline running, live control):
```json
{ "ok": true, "revision": 5, "lifecycle": "active",
  "changes": [ { "path": "video.0.bitrate_kbps", "requested": 1500, "effective": 1500, "apply": "live",
                 "status": "applied", "effective_on_next_start": false, "pipeline_restarted": false,
                 "message": "read back from encoder" } ] }
```
Restart-required (pipeline running):
```json
{ "path": "video.0.fps", "requested": 10, "effective": 10, "apply": "pipeline_restart",
  "status": "applied", "effective_on_next_start": false, "pipeline_restarted": true,
  "message": "pipeline restarted with demand preserved" }
```
Pipeline cold — the change is stored, **no hardware is started for it**:
```json
{ "path": "sensor.fps", "requested": 10, "effective": 10, "apply": "live",
  "status": "stored", "effective_on_next_start": true, "pipeline_restarted": false }
```
Rejected value (nothing clamped, nothing applied):
```json
{ "ok": false, "error": { "code": "invalid_value", "path": "sensor.fps", "message": "sensor fps outside known range" },
  "revision": 5, "changes": [ { "path": "sensor.fps", "requested": 1234, "effective": null, "apply": "live", "status": "rejected", "message": "…" } ] }
```
A restart failure returns `500 pipeline_restart_failed` with the exact stage
in `message`; the pipeline is in `failed` state (rolled back, no second
pipeline), demand is preserved, the next consumer may retry.

`status` per change: `applied` (in effect now), `stored` (persisted; effective
on next pipeline start or daemon restart, see `apply`), `rejected`.

Pipeline restarts happen exclusively inside the `PipelineManager`; the HTTP
layer never touches sensor, ISP or encoder.

### M7 image and latency controls

`capabilities.image` describes each ISP control with the same tri-state and
apply semantics as other controls. `anti_flicker` additionally lists
`["off","50hz","60hz"]`; 50 Hz is not selected globally. `wdr` and `drc`
remain visible as unsupported on the verified linear T40NN/IMX307 path.

`capabilities.latency` lists `normal|low|custom`, GOP, FrameSource/encoder
buffering, per-consumer queue depth, socket buffer and stall limit. B-frames
and an SDK low-latency switch are explicitly `unsupported` because the used
SDK 1.3.1 interface exposes neither for this path.

Example:

```json
{
  "image": { "brightness": 128, "anti_flicker": "50hz", "white_balance_mode": "auto" },
  "latency": { "profile": "low", "consumer_queue_depth": 1 },
  "video": { "0": { "gop": 20 } }
}
```

The explicit GOP overrides the profile preset. Image changes are live while
the ISP is active and stored/reapplied on the next wake while cold. Buffer
count changes use one controlled pipeline restart with demand preserved.
`state.image` contains effective configured values plus AE read-back;
`telemetry.latency` separates capture→encoder-output from
encoder-output→socket. Neither includes client decoder/display buffering.

## GET /api/v1/telemetry

```json
{ "timestamp_ms": 1758228000000, "lifecycle": "active", "pipeline_generation": 3,
  "process": { "cpu_percent": 4.2, "rss_kb": 3960, "threads": 12 },
  "media":   { "encoded_fps": 15.0, "bitrate_kbps": 1502, "dropped_frames": 0,
               "stream_fps_requested": 15, "bitrate_kbps_requested": 1500 },
  "power":   { "sensor_fps": 15, "sensor_fps_requested": 15, "isp_clock_hz": 366666000,
               "encoder_clock_hz": 550000000, "cpu_frequency_hz": 912000000, "profile": "custom" } }
```

`null` = unknown / not measurable on this platform (never `0` for "unknown").
`encoded_fps` / `bitrate_kbps` come from a 1 s window of encoder frames and
are `null` while the pipeline is cold.

## GET /api/v1/events (SSE)

`Content-Type: text/event-stream`. First event is a `state` snapshot, then:

```
event: lifecycle
data: {"from":"cold_idle","to":"starting"}

event: config_changed
data: {"revision":6,"paths":["video.0.bitrate_kbps"]}

event: telemetry
data: { …same document as GET /telemetry… }
```

Telemetry events are emitted at 1 Hz **only while at least one SSE client is
connected**. A `: keepalive` comment is sent every 15 s. Each SSE client has a
bounded queue (64 events) and a 64 KB output buffer; a client that cannot keep
up is disconnected — the media path is never blocked by SSE. An open SSE
connection is not media demand: the pipeline stays `cold_idle`.

## Persistence

Persistent configuration lives in `machino.conf` (the file given with `-c`).
`PATCH` rewrites only the managed `key = value` lines (comments and other
keys are preserved), writes to `machino.conf.tmp`, `fsync`s, `rename`s over
the original and `fsync`s the directory. `config.revision` is stored in the
file and increases by one per successful commit. Runtime state and telemetry
are never persisted.

## Vendor extensions

The schema is platform-neutral (`power.isp_clock_hz` is `power.isp_clock_hz`
on every platform). Vendor-specific extras, if ever added, live under an
optional `vendor.<name>` object that no core functionality depends on.

## Test client

`tools/webui_sim.py <camera-ip> [port]` behaves like the future WebUI: fetches
discovery/capabilities/config/state, subscribes to events, changes bitrate
and profile, verifies the reflected effective state, and checks that reading
the API never wakes the pipeline.
